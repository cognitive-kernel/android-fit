# فیت‌یار (FitYar)

فیت‌یار یک برنامه اندرویدی فارسی/انگلیسی برای ساخت و مدیریت تمرین، ثبت سوابق ورزشی و پیگیری پیشرفت است. قابلیت‌های اصلی آفلاین‌اند و داده‌ها روی دستگاه ذخیره می‌شوند. در این پروژه هیچ ویدئوی تمرینی اضافه نشده است؛ راهنمای حرکات از تصویرسازی ثابت و متن استفاده می‌کند.

## قابلیت‌های فعلی و حفظ‌شده

- ساخت، مشاهده، ویرایش و حذف برنامه‌های تمرینی و حرکات.
- ثبت تمرین با تاریخ شمسی، برنامه، حرکت، ست، تکرار و وزن.
- ذخیره محلی سوابق در SQLite.
- قدم‌شمار با حسگر سخت‌افزاری دستگاه و درخواست مجوز فعالیت بدنی؛ مقدار فعلی قدم‌ها هنگام فعال‌بودن حسگر نمایش داده می‌شود.
- خروجی CSV از سوابق.
- انتخاب زبان فارسی/English در اولین اجرا و امکان تغییر زبان از صفحه اصلی.
- پشتیبانی از RTL برای فارسی و منابع متنی انگلیسی.
- حفظ داده‌های موجود هنگام ارتقای پایگاه داده؛ ستون‌های جدید به جدول سوابق اضافه می‌شوند.

## قابلیت‌های اضافه‌شده در شاخه آماده‌سازی انتشار

- **سازنده برنامه شخصی:** ساخت برنامه پایه بر اساس هدف، سطح آمادگی، تجهیزات، تعداد جلسات هفتگی و مدت جلسه؛ برنامه تولیدشده قابل ویرایش است.
- **ثبت جزئیات تمرین:** زمان استراحت بین ست‌ها، سختی ادراک‌شده تمرین (RPE از ۱ تا ۱۰) و یادداشت شخصی، علاوه بر اطلاعات قبلی.
- **تاریخچه و تحلیل پیشرفت:** تعداد ثبت‌ها، روزهای تمرین، حجم محاسبه‌شده از ست × تکرار × وزن، بیشترین وزنه ثبت‌شده، جلسات اخیر و نمودار تصویری حجم تمرین.
- **کتابخانه حرکات با تصویرسازی ثابت:** اسکوات، شنا، لانج، پلانک، پارویی دمبل و پیاده‌روی؛ هر مورد توضیح عضلات هدف، تجهیزات و روش اجرای کلی دارد. هیچ ویدئویی در برنامه قرار نگرفته است.
- **مربی آفلاین مبتنی بر قواعد:** پیشنهادهای ساده برای استمرار، ریکاوری و پیشرفت تدریجی بر اساس سوابق و امتیاز سختی ثبت‌شده. این قابلیت تشخیص پزشکی یا جایگزین مربی نیست.
- **هدف تمرین هفتگی:** تعیین هدف از ۱ تا ۷ روز و مشاهده تعداد روزهای ثبت‌شده در هفت روز اخیر.
- **هدف قدم‌ها برای هر نوبت پیاده‌روی:** تنظیم هدف قدم و نمایش پیشرفت زنده هنگام فعال‌بودن قدم‌شمار؛ این نسخه ادعای شمارش روزانه در پس‌زمینه ندارد.
- **یادآور محلی قابل تنظیم:** انتخاب ساعت روزانه، درخواست مجوز اعلان در نسخه‌های جدید اندروید، و تلاش برای زمان‌بندی مجدد پس از راه‌اندازی مجدد گوشی.
- **پشتیبان‌گیری و بازیابی پایگاه داده:** ذخیره فایل پشتیبان در محل انتخابی کاربر و بررسی سلامت ساختار پایگاه داده پیش از جایگزینی اطلاعات. توصیه می‌شود پیش از بازیابی از اطلاعات فعلی نسخه پشتیبان تهیه شود.
- **تصویرسازی درون‌برنامه‌ای:** دارایی‌های برداری ثابت برای حرکات ورزشی، به‌جای ویدئوهای حجیم.
- **آزمون‌های تکمیلی:** بررسی ورودی‌های جزئیات تمرین، آمار هفتگی و وجود دکمه‌های قابلیت‌های جدید.

## حریم خصوصی و محدودیت‌های فعلی

- قابلیت‌های اصلی بدون حساب کاربری و بدون اتصال اینترنت طراحی شده‌اند.
- داده‌های تمرین به‌طور پیش‌فرض در پایگاه داده محلی نگهداری می‌شوند.
- در این شاخه هیچ SDK تبلیغاتی، تحلیل‌گر رفتاری یا پرداخت درون‌برنامه‌ای فعال نشده است. ادغام تبلیغات و پرداخت باید پس از انتخاب ارائه‌دهنده‌ای که برای کشور/حساب واقعی کاربر قابل استفاده باشد انجام شود؛ هویت یا کشور جعلی نباید استفاده شود.
- اتصال مستقیم به Health Connect، همگام‌سازی ابری و خرید اشتراک هنوز پیاده‌سازی نشده‌اند؛ تا زمان افزودن و آزمون واقعی نباید در معرفی برنامه به‌عنوان قابلیت موجود تبلیغ شوند.
- پیش‌نویس سیاست حریم خصوصی: [PRIVACY_POLICY.md](PRIVACY_POLICY.md). جای‌نگهدار اطلاعات تماس باید حذف و سیاست روی یک نشانی عمومی پایدار منتشر شود.

## ساخت و آزمون

- Android Studio و JDK 17
- Android SDK Platform 36
- Android Gradle Plugin 8.9.2 و Gradle 8.11.1

مخزن را در Android Studio باز کنید و Gradle Sync را اجرا کنید. برای ساخت APK از Build > Build APK(s) استفاده کنید.

GitHub Actions آزمون‌های واحد، Android Lint، آزمون‌های ابزاری روی شبیه‌ساز Android 16 و ساخت APK دیباگ و Android App Bundle را اجرا می‌کند. APK دیباگ برای نصب و آزمون اولیه است؛ برای انتشار عمومی به کلید امضای امن و نسخه release امضاشده نیاز است. کلیدها و رمزهای امضا را هرگز در مخزن قرار ندهید.

## چک‌لیست پیش از انتشار عمومی

- اجرای موفق CI و رفع تمام خطاهای build، lint و آزمون‌های ابزاری.
- نصب APK روی گوشی واقعی و آزمون زبان، ساخت/ویرایش/حذف برنامه، ثبت تمرین، CSV، نمودار، پشتیبان‌گیری و بازیابی، مجوزها و یادآورها.
- بررسی نسخه پشتیبان روی فایل آزمایشی؛ بازیابی فایل ناشناس یا خراب نباید اطلاعات جاری را جایگزین کند.
- تولید نسخه release امضاشده، نگهداری امن upload key و افزایش versionCode برای انتشار بعدی.
- تکمیل فهرست فروشگاه، اطلاعات ایمنی و محتوا، نشانی سیاست حریم خصوصی و اطلاعات پشتیبانی.
- قبل از فعال‌کردن تبلیغات/پرداخت، بررسی شرایط احراز هویت، دریافت وجه و سیاست‌های شبکه/فروشگاه.

> وضعیت ساخت نهایی باید بر اساس نتیجه آخرین اجرای GitHub Actions ثبت شود؛ تغییر کد به‌تنهایی به معنی موفقیت build یا آمادگی انتشار نیست.
