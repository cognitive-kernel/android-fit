# راهنمای پشتیبان‌گیری، نصب و به‌روزرسانی فیت‌یار

## سیاست قطعی امضای نسخه‌های آینده

از اولین نسخه‌ای که به‌عنوان نسخهٔ مبنای جدید منتشر می‌شود، یک کلید امضای ثابت برای بستهٔ `com.cognitivekernel.androidfit` تعیین خواهد شد. تمام نسخه‌های بعدی همین بسته باید با همان کلید ساخته شوند و `versionCode` در هر انتشار افزایش یابد.

**وضعیت فعلی:** نامزد `1.1.14` با `versionCode=110` ساخته شده است. CI وجود ۶۵۵۶ GIF، شناسهٔ بسته، نسخه و امضای دائمی را تأیید کرده و آزمون‌های واحد، Lint، آزمون ابزاری شبیه‌ساز و ساخت APK آزمایشی موفق‌اند. اثرانگشت گواهی انتشار دائمی `61:DB:AC:4C:3B:39:36:AD:0D:A7:5C:02:17:81:D1:94:D9:97:DE:0E:67:18:E0:F1:53:C8:5F:14:62:9F:0C:4A` در CI قفل شده است. بااین‌حال، مقایسهٔ گواهی APK با نسخهٔ نصب‌شده و حفظ داده‌ها باید روی همان گوشی آزمایش شود؛ بنابراین سازگاری نصب درجا هنوز تضمین نشده است. [دریافت artifact نامزد](https://github.com/${repo}/actions/runs/40462096719/artifacts/12714863722) · [جزئیات کلید](ANDROID_SIGNING.md).

گواهی انتشار دائمی مستند و در CI قفل شده است؛ تمام نسخه‌های بعدی بستهٔ `com.cognitivekernel.androidfit` باید با همان کلید ساخته شوند و `versionCode` را افزایش دهند. هنوز باید گواهی نسخهٔ نصب‌شده روی گوشی با اثرانگشت بالا مقایسه شود. پیش از آزمون، از اطلاعات پشتیبان بگیرید؛ برنامه را حذف نکنید. پشتیبان دیتابیس جایگزین کلید امضا نیست و به‌تنهایی امکان نصب APK با امضای متفاوت روی نصب موجود را فراهم نمی‌کند.

## پیش از نصب یا به‌روزرسانی

1. از اطلاعات برنامه خروجی/پشتیبان تهیه کنید و فایل را خارج از پوشهٔ موقت برنامه نگه دارید.
2. نام بسته را بررسی کنید: `com.cognitivekernel.androidfit`.
3. برای نصب روی برنامهٔ موجود، گواهی APK جدید باید دقیقاً با گواهی نصب‌شده یکسان باشد.
4. `versionCode` نسخهٔ جدید باید از نسخهٔ نصب‌شده بیشتر باشد.
5. اگر گواهی‌ها متفاوت‌اند، نصب به‌صورت آپدیت انجام نمی‌شود. فقط در مهاجرت برنامه‌ریزی‌شده به نسخهٔ مبنای جدید، پس از بررسی پشتیبان، نصب مجدد انجام دهید.

## بررسی امضای APK

با Android SDK Build Tools:

```bash
apksigner verify --print-certs fit-yar.apk
```

مقدار `Signer #1 certificate SHA-256 digest` را بررسی کنید. برای نسخه‌های انتشار آینده باید با اثرانگشت ثابت ثبت‌شده در [ANDROID_SIGNING.md](ANDROID_SIGNING.md) یکسان باشد.

## خروجی و بازیابی نسخهٔ پشتیبان

در صفحهٔ اصلی، گزینهٔ **«بازیابی پشتیبان / دیتابیس»** دو قالب را می‌پذیرد: پشتیبان انتخابی JSON که خود برنامه می‌سازد، و فایل کامل SQLite فیت‌یار (معمولاً با پسوند `.db`). برای فایل SQLite، برنامه یکپارچگی SQLite، نسخهٔ پایگاه داده، جدول‌ها و ستون‌های موردنیاز را بررسی می‌کند؛ سپس تأیید صریح جایگزینی کل اطلاعات را می‌خواهد و نسخهٔ بازگشت موقت از پایگاه دادهٔ فعلی می‌سازد. فایل نامعتبر یا ناسازگار نباید بازیابی شود.

1. پیش از آزمون بازیابی، یک خروجی تازه از اطلاعات فعلی تهیه کنید.
2. فایل خروجی را در محل دیگری نگه دارید؛ به حافظهٔ موقت یا تنها نسخهٔ موجود در گوشی اکتفا نکنید.
3. بازیابی را ابتدا روی دادهٔ آزمایشی انجام دهید.
4. پس از بازیابی، برنامه‌ها، سوابق تمرین و داده‌های سلامت را با وضعیت قبل از خروجی مقایسه کنید.

## نصب نسخهٔ آزمایشی کنار برنامهٔ فعلی

گردش‌کار GitHub Actions یک APK جدا با شناسهٔ بستهٔ `com.cognitivekernel.androidfit.test2` می‌سازد. فایل `fityar-test-side-by-side.apk` را از بخش **Artifacts** اجرای موفق مربوط به شاخهٔ آن PR دریافت کنید. این نسخه برنامه‌ای جداست و داده‌های برنامهٔ اصلی را نمی‌خواند یا به‌روزرسانی نمی‌کند. ساخت موفق APK به‌تنهایی به معنی موفقیت همهٔ آزمون‌ها نیست.

**APK آزمایشی برای به‌روزرسانی نصب اصلی استفاده نشود.**
